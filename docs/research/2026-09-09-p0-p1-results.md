# P0/P1 实测：外部 Python 自动下载大 QMT 行情

北京时间 2026-09-09 11:40 记录。状态：**单日小样本闭环通过，尚未完成生产迁移或交易验收。**

## 结论

外部 Python → 本机文件桥 → 大 QMT 内置全局 `download_history_data` → 原始缓存读取 → 外部 DataFrame 校验，这条自动取数链在当前模拟终端实测成立。用户只需启动一次桥接策略，本轮没有通过界面手工下载数据，也没有连接原生 xtquant 服务。

当前发行版的 `bigqmt_bridge.InnerBackend.download_*` 仍只是只读缓存确认接口。本轮真实下载在独立的 `experiments/qualification_v1` 中执行；不能把实验通过误认为发行版已经支持自动下载。

## 环境与依赖

- 国金 QMT 模拟客户端，内置 Python 3.6.8；请求由已确认的模拟客户端进程处理。
- 外部 conda Python 3.10；原始行情序列化留在内置端，pandas/时间转换留在外部。
- `download_history_data` / `down_history_data` 是注入的**全局函数**，不是 ContextInfo 方法。批量 `download_history_data2` 在本次探针中不存在。
- `C.get_market_data_ex_ori`、`C.get_full_tick` 可用。读取显式保留 `subscribe=False`、`fill_data=False`、`dividend_type='none'`。
- `importlib`、`socket`（缺 `_socket`）、`ctypes`（缺 `_ctypes`）、Redis、ZMQ、pandas、numpy 导入失败；queue/threading 可以导入，但没有启动线程或据此认定 QMT API 线程安全。
- `passorder`、`cancel`、`get_trade_detail_data` 全局函数及订阅方法仅检查存在性；**没有调用交易接口、没有进行订阅测试**。
- 常见的全局/ContextInfo 财务下载函数名均未探测到。财务读取入口存在不代表自动财务更新成立。

因此，复审报告中的两个候选项目不能原样部署：第一候选的 Redis/ZMQ 路径缺少依赖，CFQuant 通用/LITE 入口涉及的 importlib/ctypes 同样不满足本机条件。这是当前导入探测结论，不代表所有券商版本都不支持这些方式。未安装候选整包、未补入终端模块、未修改权限检查。

## 发现并修复的外部解析问题

### 1. 原始 UTC 时间被丢弃

第一份日线下载后原始响应同时包含：

- `time=1788796800000`，即北京时间 2026-09-08 00:00:00；
- `stime='20260907'`，与本机 America/Los_Angeles 时区显示一致。

旧规范化逻辑按请求字段构造 DataFrame，把未显式请求的原始 `time` 丢掉，再把 `stime` 当北京时间，导致日期校验失败。不是“下载了错误交易日”，也不能将目标日期改成前一天来放行。

修复后，在列字典和记录字典格式中保留原始 `time`，优先采用 UTC 毫秒；该字段存在但值为空时会报错，不偷偷退回看似合理的 `stime`。没有更改操作系统时区或覆盖券商文件。完全不带 `time` 字段的字典或位置行仍沿用既有字符串解释，**本轮没有证明这些旧格式在任意系统时区下都安全**；正式迁移时需要单独规定严格 UTC 时间合同。

### 2. 空缓存格式识别遗漏

真实空缓存是包含 `time/stime/open/...` 键、每列均为空数组的对象，而不仅是 `[]` 或 `{}`。补充这种结构的冷缓存识别，缓存不完整与真正空缓存仍分开处理。

保留了第一份日线失败原始报告，未覆盖为成功；修复后对原始响应重新校验通过，并额外发出一次**只读**请求确认缓存可读，没有重发日线下载。其余后续样本使用修复后的解析器。

回归采用测试驱动：新增案例先出现 **4 failed / 27 passed**，修复后完整既有与实验测试为 **85 passed**。独立代码审查指出无 `time` 字段的旧格式仍有时区边界，文档据此收紧承诺。没有修改运行中的实验 worker，所以用户不需要重新加载入口。

## 选型调整与下一步

1. 当前终端以已验证的最小内置执行端和本机文件通道作为第一落地方向，继续参考候选项目的接口映射，不强行部署缺少依赖的运行时。文件通信不妨碍外部环境保留全部业务逻辑，但秒级调度尚不能保证交易时延要求。
2. 将本次下载实验整理成正式外部下载任务接口：分块、进度、缓存读回、部分缺失、超时/结果未知、有限重试与背压；先单任务影子输出，不接生产数据库。自动下载与只读缓存模式必须清晰区分。
3. 单独推进账户只读与回调接入。订单生命周期、持久请求 ID/去重/未知状态对账完成后，才按明确模拟账户、标的、数量、价格做下单/撤单验证；当前实验没有交易端点。
4. 财务自动供应、复权、完整合约、北京市场、指数成分全集继续逐项验收。不把行情下载成功扩展为全数据供应成功。
5. 全市场容量、历史窗口、混合负载、断线恢复和跨端一致性通过后，再安排生产批次边界切换。原调度与采集配置本轮保持不变。
